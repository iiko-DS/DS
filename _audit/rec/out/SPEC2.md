## Что нужно на каждый компонент

### 1. `out\previews\<slug>.json` — блок «На экране» из ДВУХ экранов

```json
{"slug": "<slug>", "preview_html": "<div class=\"phones\">…</div>"}
```

Правила:

- **ровно два `phones__item`** (было три — третий убрать);
- на обоих экранах **один и тот же интерфейс** (тот же экран приложения: та же шапка,
  тот же список/форма, те же данные);
- **изучаемый компонент виден на обоих экранах**, но стоит в разных местах:
  на первом — в теле экрана (список, форма), на втором — в шторке снизу
  (`phone__scrim` + `phone__sheet`) или в другом естественном месте (шапка, футер, карточка).
  Если для компонента шторка не бывает (логотип, статус, дивайдер, скролл) — второе место
  подбираем по смыслу: шапка ↔ карточка, строка списка ↔ плашка, тело ↔ футер;
- первый экран — **значения как рекомендовано** (он не меняется правками);
- подписи (`phone__caption`) короткие и честные: что именно показано на этом экране;
- разметка — дословно классы ДС (брать из `data\<slug>.json`, поле `examples[].html`,
  и из `_audit\rec\mock.py`: `status/head/body/foot/line/actions/lst/search/input_field/btn/iconbtn/checkbox/radio/toggle/tabs/sheet/card/chips/divider/icons/plain_icon/screen/phones`);
- `mock.check_balance(html)` должен вернуть `0`; классы должны существовать в CSS ДС
  или в разметке страниц (`ds-*`), каркасные — в `rec.css`;
- внутри экрана ничего не должно вылезать: ширина экрана 375 px, тело с паддингами 16 —
  содержимое шире 343 px обрежется.

### 2. `out\edits\<slug>.json` — строки таблицы: цифры и поля «Правка»

```json
{"slug": "<slug>", "edits": [
  {"row": 1, "mobile": "48 px — вся строка, нажатие по всей строке",
   "edits": [{"id": "row", "v": 48, "sel": ".ds-checkbox", "css": "min-height:@px"}]},
  {"row": 3, "mobile": "14 / 20 px"}
]}
```

Что делать:

1. **«то же / та же / тот же / те же / также» → цифры.** Там, где в колонке Mobile стоит
   такое слово, а в колонке Desktop есть размеры (px/dp/pt, «16 / 24», «20 × 20»), в Mobile
   пишем те же размеры цифрами. Смысл фразы сохраняем, если он полезен («то же — ось темы»
   → «8 px, 1 px — то же, ось темы»), но цифры обязаны быть.
   Если в Desktop размеров нет (только цвета, состояния, поведение) — строку не трогаем.
2. **Поля «Правка»** для каждой строки, у которой в Mobile теперь есть конкретное число:
   `v` — это число, `sel` — селектор компонента, `css` — свойства с `@` вместо числа.
   Поля должны попадать в разметку **второго экрана** твоего превью (и в панели страницы):
   проверь, что класс из `sel` есть в твоём `preview_html`.
   Правило пишется на странице как
   `[data-mode="mobile"][data-preview="edit"].phone__screen <sel> { … }`.
   Если в разметке компонента стоит inline-стиль (например `style="min-height:48px"`),
   добавь `!important`, иначе правка не сработает — то же, если мобильный слой ДС задаёт
   значение более длинным селектором.
3. Строки, у которых поля уже есть (смотри текущий `data\<slug>.json` → `changes[].edit`),
   переписывать не нужно — если только текст Mobile не меняется: тогда укажи строку с `mobile`
   и, при необходимости, с `edits` (тогда массив полей заменится целиком).
4. Одна строка — один объект в списке. `"edits"` включай только если поля меняются.
