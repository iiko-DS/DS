# Дизайн-система iiko — рабочая папка

Здесь лежит ДС iiko и инструменты, которыми собираются её страницы.

Важно: это **не один репозиторий, а четыре**, и они должны лежать рядом в одной папке — генератор страниц обращается к соседним папкам по относительным путям (`iiko-ds-web` и `iiko-ds-mobile`). Все четыре живут в организации **iiko-DS** (`https://github.com/iiko-DS`).

## Структура

```
DS/
├── iiko-ds-web/          репозиторий: компоненты, токены, стили, спецификация
├── iiko-ds-mobile/       репозиторий: мобильный слой ДС
├── iiko-ds-prototypes/   репозиторий: прототипы экранов (в том числе KDS)
├── _audit/               генератор страниц и данные, из которых они собираются
│   ├── rec/build.py                  сборка страниц компонентов
│   ├── rec/mock.py                   мок-данные, которые страницы показывают в примерах
│   ├── rec/data/<slug>.json          данные страницы компонента (что видно на странице)
│   ├── rec/data-tech/<slug>.json     технические заметки: источники, платформа, замеры
│   ├── rec/icon-map.json, icons.py   иконки для страниц
│   ├── rec/apply-values.py           применение пачки правок к data/*.json
│   ├── rec/out/                      превью, дайджесты и SPEC-инструкции по сборке
│   ├── platform/<slug>.json          данные платформы для мобильного слоя
│   └── platform/_src/                скрипты, которыми собираются platform/*.json
└── serve.py              локальный сервер, чтобы смотреть страницы в браузере
```

Сам этот корневой каталог — тоже репозиторий (`iiko-DS/iiko-ds`): генератор, данные и `serve.py`.

## Как начать работу

Подробно, с нуля — для дизайнера, который подключается впервые.

### 1. Что понадобится

- **Доступ в организацию iiko-DS** — его выдаёт владелец: `https://github.com/orgs/iiko-DS/people` → `Invite member`. Без приглашения приватные репозитории не клонируются.
- **Git** — чтобы склонировать репозитории и присылать правки. Проще всего поставить **GitHub Desktop** и войти в свой аккаунт: он сам разберётся с авторизацией, токены руками вводить не нужно.
- **Python 3** — и всё. Генератор использует только стандартную библиотеку, сторонних пакетов ставить не нужно.
- Любой редактор, удобнее всего VS Code: `Файл → Открыть папку` и выбрать папку `DS` целиком — тогда видны все четыре репозитория сразу.

Проверить Python:

```
python --version      # Windows
python3 --version     # macOS и Linux
```

Нужен ответ вида `Python 3.x.x`. Если команда не найдена — поставить Python с python.org (галочка «Add Python to PATH» на Windows) и перезапустить терминал.

### 2. Куда клонировать

Все четыре репозитория — **в одну папку** (её имя любое, в примере `DS`). Генератор ищет соседние папки по относительным путям, поэтому рядом должны лежать `iiko-ds-web` и `iiko-ds-mobile` — **имена этих двух папок менять нельзя**, иначе генератор их не найдёт.

```
mkdir DS
cd DS
git clone https://github.com/iiko-DS/iiko-ds.git .           # генератор, данные, serve.py
git clone https://github.com/iiko-DS/iiko-ds-web.git         # компоненты, токены, стили
git clone https://github.com/iiko-DS/iiko-ds-mobile.git      # мобильный слой ДС
git clone https://github.com/iiko-DS/iiko-ds-prototypes.git  # прототипы экранов
```

В GitHub Desktop это то же самое без командной строки: `File → Clone repository → GitHub.com` и выбрать четыре репозитория по очереди, каждый — в ту же папку.

Должно получиться так:

```
DS/
├── README.md              этот файл
├── serve.py               локальный сервер для просмотра
├── _audit/                генератор страниц и данные
├── iiko-ds-web/           компоненты, токены, стили (десктопный слой ДС)
├── iiko-ds-mobile/        мобильный слой ДС
└── iiko-ds-prototypes/    прототипы экранов
```

Три репозитория из четырёх приватные. Если какой-то из них не клонируется — нет доступа, попроси приглашение у владельца организации.

Собранных страниц в репозиториях нет: `iiko-ds-mobile/prototypes/recommendations/` — это вывод генератора, он не коммитится и появляется после первой сборки.

### 3. Собрать страницы

```
python _audit/rec/build.py        # Windows
python3 _audit/rec/build.py       # macOS и Linux
```

Что должно появиться в консоли (в конце):

```
page: tabs.html
page: textarea.html
page: timepicker.html
page: tree.html
page: table-2-lvl.html
page: text-ui.html
index.html, components: 38
```

`index.html, components: 38` означает, что собралось 38 страниц компонентов плюс индекс. Результат — в `iiko-ds-mobile/prototypes/recommendations/`: 40 html-файлов плюс общие `rec.css` и `rec.js`. Именно эти файлы открываются и показываются на ревью.

Важно: **страницы генерируются, руками их не правим** — при следующей сборке правки затрутся. Всё, что видно на странице, правится в данных (см. «Где что править»).

### 4. Посмотреть локально

```
python serve.py            # порт по умолчанию 8899
python serve.py 9000       # если порт занят — можно другой
```

Сервер напечатает адрес, обычно:

```
Сервер без кэша: http://127.0.0.1:8899/
Страницы: http://127.0.0.1:8899/iiko-ds-mobile/prototypes/recommendations/index.html
```

Открыть вторую ссылку — это список всех компонентов. Сервер отдаёт файлы без кэша, поэтому после пересборки достаточно обновить страницу, `Ctrl+F5` не нужен.

На страницах есть форма ревью: когда дизайнер оставляет решение по компоненту, оно сохраняется в `_audit/rec/review/<компонент>.<имя>.json` — по одному файлу на человека, поэтому решения разных людей не затирают друг друга, а файлы можно коммитить и обсуждать вместе.

### 5. Короткие команды на каждый день

```
python pull.py     # обновить все четыре репозитория из организации
python start.py    # собрать страницы и открыть сервер (то же, что build.py + serve.py)
python doctor.py   # что-то не работает — проверить окружение, ничего не меняя
```

`pull.py` ничего не тронет, если в репозитории лежат незакоммиченные правки или ты сидишь в своей ветке: он об этом сообщит. `doctor.py` проверяет Python, наличие четырёх папок рядом, адреса их origin и собраны ли страницы — это первое, что стоит запустить при любой непонятной ошибке.

Новичку проще начать с короткой инструкции — [START-HERE.md](START-HERE.md): что поставить и какие три команды выполнить.

### 6. Куда попадает правка

1. Правим данные: `_audit/rec/data/<slug>.json` (что видно на странице) или `_audit/rec/data-tech/<slug>.json` (технические заметки).
2. Пересобираем: `python _audit/rec/build.py`.
3. Смотрим результат в браузере.
4. Коммитим и пушим **в том репозитории, который правили**:
   - данные и генератор — в `iiko-ds` (корень);
   - CSS компонентов — в `iiko-ds-web`;
   - мобильные значения и мобильный CSS — в `iiko-ds-mobile`;
   - прототипы экранов — в `iiko-ds-prototypes`.

## Как мы работаем вместе

Правило простое: **`main` — общая база, свои пробы — в своей ветке, в общее — через Pull Request.**

- **`main` — база для всех.** Это то, чем пользуются все: собранные страницы, данные, стили. Прямо в `main` не пишем.
- **Свои пробы — в своей ветке.** В GitHub Desktop: `Current Branch → New Branch`, имя вида `ivan/badge-fix`. В своей ветке можно делать что угодно: у остальных `main` остаётся чистым, и их `git pull` не ломается.
- **«Вот это стоит взять всем» — это Pull Request.** Когда проба получилась: `Push origin` → `Create Pull Request` в `main`. Видно, что именно меняется, можно обсудить в комментариях и влить. Так «важное и интересное» попадает в общую базу, а не переписывается руками.
- **Перед началом работы и после чужого PR — `git pull`** в `main`, чтобы база была свежая.

Почему не «копим локально, потом перенесём руками»: если держать несохранённые правки поверх `main`, первый же `git pull` из организации упрётся в «local changes would be overwritten», и разбирать это придётся по файлам. Ветка — это и есть «локально своё, в общее только важное», только без потери правок.

Ограничение, о котором стоит знать: на бесплатном плане **защита ветки в приватных репозиториях недоступна** (protected branches — только для публичных на Free, для приватных нужен платный план). Значит «в `main` только через Pull Request» — договорённость, а не настройка, которую нельзя обойти.

### Что коммитим, а что нет

- **Коммитим:** данные страниц (`_audit/rec/data/*.json`), технические заметки, CSS компонентов, прототипы, скрипты генератора.
- **Не коммитим:** собранные страницы (`iiko-ds-mobile/prototypes/recommendations/`) — каждый собирает их у себя одной командой.

### 7. Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `python: command not found` | Python не установлен или не в PATH. Установить с python.org, перезапустить терминал. На macOS/Linux пробовать `python3` |
| Репозиторий не клонируется | Нет доступа в организацию iiko-DS — попросить приглашение у владельца |
| Страницы собрались, но без стилей | Папки `iiko-ds-web` (или `iiko-ds-mobile`) нет рядом с `_audit` — проверить, что клонировано в одну папку и с правильными именами |
| `Порт 8899 занят` | Запустить `python serve.py 9000` или остановить старый сервер |
| В консоли нет строк `page: …` | Запущена не та команда или не из папки `DS` — проверить, что текущая папка та, где лежат `_audit` и `serve.py` |
| Правки на странице пропали | Правили сам html вместо данных — вернуть `git checkout` и править `_audit/rec/data/<slug>.json` |
| `pull` ругается на local changes | Правки лежат в `main` вместо своей ветки — перенести их в ветку (`Current Branch → New Branch` переносит изменения) и вернуть `main` чистым |

## Где что править

- **Значения компонента на странице** — `_audit/rec/data/<slug>.json`, затем `python _audit/rec/build.py`.
- **Технические заметки по компоненту** (источники, платформенная спецификация, замеры) — `_audit/rec/data-tech/<slug>.json`.
- **Мобильные значения** — `_audit/platform/<slug>.json`; пересобрать их из исходников можно скриптами в `_audit/platform/_src/`.
- **CSS компонентов** — в своих репозиториях: `iiko-ds-web/components/…`, `iiko-ds-mobile/components/…`.
- **Прототипы экранов** — в `iiko-ds-prototypes/`.

## Что не коммитим

- Секреты: `.env`, `.env.*`, `.vscode/mcp.json` (в нём токен Figma — для команды есть `.vscode/mcp.example.json`).
- Кэш Python: `__pycache__/`, `*.pyc`.
- Разовые проверочные материалы: снимки экрана, пробы, временные страницы замеров.
